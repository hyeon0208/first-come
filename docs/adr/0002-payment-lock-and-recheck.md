# 결제는 트랜잭션 밖에서 부르고, 부르기 전에 좌석을 "결제 중"으로 잠그며, 승인 뒤 조건을 다시 확인한다

결제는 느린 외부 호출이라 DB 트랜잭션과 좌석 잠금을 쥔 채 부르지 않는다. 그러면 결제 전에 확인한 조건이 결제 뒤에는 달라져 있을 수 있고, 같은 선점에 결제가 두 번 나갈 수 있다. 그래서 세 단계로 나눈다.

1. 짧은 트랜잭션: 선점 좌석을 조건부 UPDATE로 "선점 → 결제 중"으로 바꾼다. 바뀐 행 수가 좌석 수와 다르면 결제 서버를 부르지 않고 거절한다. 멱등 키가 달라도 마찬가지다.
2. 트랜잭션 없이 결제를 부른다.
3. 짧은 트랜잭션: 예매 가능 시간이 남았고 공연 시작 시각 전일 때만 "결제 중 → 예매 완료"로 바꾸고 예매를 확정한다. 어긋나면 확정하지 않고 결제를 자동 취소한 뒤 시간 초과로 응답한다.

결제가 거절되면 좌석을 선점으로 되돌린다. 응답을 받지 못하면 승인됐을 수 있으므로 주문 번호로 취소를 보내고, 취소가 확인된 뒤에만 좌석을 선점으로 되돌린다. 멱등 키는 같은 키로 다시 온 요청에 앞선 결과를 돌려주는 데만 쓴다.

## Considered Options

- 멱등 키만으로 중복 방지: 키가 다른 요청은 막지 못한다(과거에 실제로 결제가 두 번 나갔다).
- 예매 테이블의 유일 제약으로 진행 중 결제를 하나로 제한: 좌석 쪽에서 결제 중인지 알 수 없어, 결제 중인 좌석이 "좌석 다시 고르기"로 풀릴 수 있다.
- 한 트랜잭션에서 결제까지: 결제 지연이 곧 좌석 잠금 지연이 된다.

## Consequences

- 결제 도중 서버가 멈추면 "결제 중" 좌석이 남는다. 회차가 끝날 때 함께 정리되고, 서버가 다시 뜨면 진행 중 회차를 모두 중단으로 끝낸다.
- 자동 취소가 실패하면 승인된 결제가 남는다. 예매 행에 승인 번호를 남기고 ERROR 로그를 쓴다. 대사 작업은 2단계(Outbox)에서 다룬다.
- 결제 중에는 타이머가 끝나도 좌석을 풀지 않는다. 성공인지 시간 초과인지는 3단계가 정한다. 다만 결제 결과가 끝내 오지 않아(취소도 실패) 결제 중으로 남은 좌석이 회차를 붙잡지 않도록, 예매 가능 시간이 끝나고 1분이 더 지나면 회차를 시간 초과로 끝낸다.
