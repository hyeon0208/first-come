# 로그인 없이 닉네임과 서버 세션 쿠키로 사용자를 구분한다

사용자는 닉네임만 넣는다. 서버는 사용자를 만들고 추측할 수 없는 무작위 토큰을 HttpOnly 쿠키로 내려 준다. 이후 요청은 쿠키로 사용자를 찾는다. 사용자 번호를 헤더나 본문으로 받지 않으므로 남의 회차를 조작할 수 없다. 개인 정보를 받지 않고 Spring Security도 넣지 않는다.

## Considered Options

- 아이디·비밀번호 또는 소셜 로그인: 기기를 바꿔도 기록이 이어지지만 가입 화면, 비밀번호 저장, 개인 정보 처리가 1단계에 더해진다. 1단계의 목표는 동시성과 결제다.
- 브라우저에 저장한 사용자 번호를 헤더로 보내기: 번호를 아는 사람이 남의 연습을 조작할 수 있다.

## Consequences

- 쿠키를 지우거나 브라우저를 바꾸면 새 사용자가 된다.
- 순위(4단계)는 닉네임 기준으로 낼 수 있다. 닉네임이 겹칠 수 있으므로 유일하게 할지는 4단계에서 정한다.
