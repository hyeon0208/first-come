# 좌석 상태는 회차 좌석 행에 두고, 가선점·선점·결제 중·확정은 조건부 UPDATE로 바꾼다

같은 좌석을 여러 참가자가 동시에 누르면 한 명만 가져가야 한다. 회차를 만들 때 좌석 수만큼(1,008행) 회차 좌석 행을 만들고, 상태(선택 가능, 가선점, 선점, 결제 중, 예매 완료)와 가진 참가자, 만료 시각을 그 행에 둔다. 상태를 바꾸는 모든 문장은 "지금 이 상태이고, 이 참가자의 것이고, 만료되지 않았을 때만"을 WHERE에 넣은 UPDATE이고, 바뀐 행 수로 성공을 판정한다. 만료는 별도 해제 작업 없이 만료 시각과 현재 시각(주입된 Clock)을 비교해 판정한다. 여러 좌석을 함께 바꿀 때는 id 순으로 먼저 잠근다.

## Considered Options

- Redis 분산 락과 TTL: 1단계에서는 근거가 없다. 2단계 부하 측정에서 DB가 먼저 막히는 것이 확인되면 그때 넣는다.
- 낙관적 락(@Version): 충돌을 커밋 시점 예외로만 알 수 있어 거절 사유를 구분하기 어렵다.
- 선점 이력 테이블 + 유일 제약: 만료된 행이 남아 MySQL에서 "유효한 행만 유일"을 걸기 어렵다.

## Consequences

- 만료된 가선점·선점 행은 다음 요청이 덮어쓸 때까지 그 상태로 남는다. 조회와 변경이 모두 만료 시각으로 판정하므로 문제없다.
- "선택 가능" 판정이 조회용 코드와 UPDATE 조건 두 곳에 있다. 같은 경계값 테스트로 함께 검증한다.
- 범위 UPDATE가 인덱스 빈 구간을 잠가 교착하지 않도록, 트랜잭션은 모두 READ COMMITTED로 실행한다(연결 풀 기본값). 좌석을 바꾸는 문장이 좌석 서비스와 예매 서비스 양쪽에서 불리기 때문에 일부 메서드에만 걸지 않는다.
