# 가상 경쟁자는 사용자와 같은 서비스 경로로 가선점부터 예매 확정까지 간다

가상 경쟁자는 화면 연출이 아니라 참가자다. 회차마다 저장한 난수 씨앗으로 도착 시각, 매수(1~4), 노리는 좌석을 정하고, 사용자 요청이 타는 것과 같은 애플리케이션 서비스를 불러 가선점 → 선점 → 결제 → 확정을 한다. HTTP는 거치지 않는다. 선점은 7분 뒤 풀리므로 확정까지 가야 "가져간 좌석은 놓지 않는다"가 예외 없이 성립한다.

## Considered Options

- 선점에서 멈추기: 결제 호출이 없어 가볍지만, 7분 뒤 좌석이 풀리지 않게 하는 가상 경쟁자 전용 예외가 필요하다.
- 좌석 행을 직접 UPDATE: 가장 가볍지만 사용자와 다른 경로라 경쟁이 실제가 아니게 된다.
- HTTP로 자기 자신을 호출: 가장 실제에 가깝지만 1단계에서는 서블릿 스레드만 잡아먹는다. 2단계 대기열에서 다시 본다.

## Consequences

- 어려움 한 회차에 결제 호출 약 400건이 10여 초에 몰린다. 가상 스레드로 돌리고, 동시에 진행되는 회차 수에 상한을 둔다.
- 가상 경쟁자의 일정은 메모리에 있다. 서버가 다시 뜨면 진행 중이던 회차는 중단으로 끝낸다.
- 같은 씨앗이면 같은 계획(들어오는 시각, 매수)이 나와 난이도 조정과 테스트를 되풀이할 수 있다.
- 가상 경쟁자는 좌석 상태를 매번 읽지 않고, 자기들이 잡았거나 거절당한 좌석을 기억해 그 밖에서 고른다. 남은 좌석이 없어 보일 때만 좌석 상태를 새로 받는다(사용자의 새로고침과 같다). 그래서 사용자가 놓은 좌석은 그 뒤에 들어온 가상 경쟁자가 가져갈 수 있고, 모두 들어온 뒤에 놓은 좌석은 남는다.
